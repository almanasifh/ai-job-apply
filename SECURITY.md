# Security Policy

## Supported version

Security and privacy fixes are applied to the latest published release.

## Report a vulnerability

Use GitHub's private vulnerability reporting from the repository **Security** tab. Do not open a public issue for suspected vulnerabilities, leaked applicant data, credentials, tokens, authenticated sessions, or private filesystem paths.

Include the affected version, impact, reproduction steps using fictional data, and any suggested mitigation. Remove real applicant information and secrets from screenshots, logs, fixtures, and attachments.

Use public GitHub issues only for non-sensitive defects and feature requests.
